Fase 6: Core Web e Persistência de Dados

Data de Emissão: 24 de Setembro de 2026

Este documento certifica o encerramento da Fase 6, estabelecendo o padrão ouro para a fundação da API Django e dos Bancos de Dados no cluster Docker Swarm. Todas as decisões foram homologadas pelo painel de especialistas (Arquiteto, DevOps, Backend e IA).

1. Persistência de Dados (PostgreSQL 16)

Foi adotada a imagem pgvector/pgvector:pg16 em preparação para a Fase 7 (RAG). A arquitetura garante injeção segura de senhas via Docker Secrets em RAM (sufixo _FILE), isolamento absoluto na rede scsi_data e pinagem estrita de volume via labels do Swarm (db_node == "true") para evitar orfandade de discos locais.

2. Cache e Sessões (Redis 7)

Utilização da variante redis:7-alpine. Implementou-se um *hotfix* avançado no entrypoint para injetar senhas dinamicamente em um redis.conf efêmero, evitando vazamentos via comando ps no host. O limite rígido de memória foi configurado via --maxmemory e política volatile-lru para prevenir interrupções abruptas pelo OOM Killer.

3. Arquitetura da API (Django + ASGI)

Abandono do padrão monolítico WSGI. Em prol da Inteligência Artificial Generativa, a aplicação foi projetada para rodar via Gunicorn + Uvicorn Workers (ASGI), viabilizando o Streaming não-bloqueante de tokens. O sistema foi integrado ao Traefik com TLS habilitado na borda e rotinas estritas de Healthcheck para garantir deploys sem downtime.

4. Otimização de Build (Dockerfile Multi-stage)

Adoção da imagem python:3.12-slim para evitar conflitos de bibliotecas musl libc inerentes ao Alpine. O build é guiado pelo gerenciador ultra-rápido Astral uv em dois estágios, isolando as dependências de compilação da imagem final. O container é selado em execução como usuário não-root (appuser), fechando o perímetro de segurança.
